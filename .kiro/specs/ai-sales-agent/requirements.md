# Requirements Document

## Introduction

The AI Sales Agent is an intelligent autonomous agent integrated into the existing Omnichannel SaaS CRM platform (Cloudflare Workers + Hono). It acts as a virtual sales representative, customer support agent, and appointment scheduler that communicates with customers via WhatsApp. Inspired by HaloAI, this feature enables tenants to deploy AI agents that can explain products, handle inquiries, negotiate, close sales, schedule appointments, and resolve customer issues — all while maintaining natural Bahasa Indonesia conversation with guardrails against hallucination and policy violations.

The AI Sales Agent integrates with existing platform services (Go-Wa messaging, iPaymu billing, contacts, files) and introduces a novel Human Escalation & Dynamic Knowledge system where the AI learns from human staff in real-time.

## Glossary

- **AI_Agent**: The autonomous conversational AI module that processes incoming messages, generates contextual responses, and triggers actions on behalf of a tenant
- **Tenant**: An organization using the CRM platform, identified by tenant_id derived from Clerk Organization ID
- **Knowledge_Base**: A per-tenant collection of FAQ entries, product information, pricing, policies, and business rules that the AI_Agent references for generating responses
- **Product_Catalog**: A structured subset of the Knowledge_Base containing product descriptions, pricing, images, and availability information
- **Escalation_Service**: The subsystem that detects when the AI_Agent lacks information and sends inquiries to designated staff members via WhatsApp, then incorporates their responses
- **Staff_Contact**: A designated human team member configured per tenant who receives escalation messages and provides information back to the AI_Agent
- **Conversation_Context**: The accumulated history of messages between a contact and the AI_Agent within a session, used to maintain coherent multi-turn dialogue
- **Lead_Scorer**: The module that evaluates conversation signals to assign qualification scores (hot, warm, cold) to contacts
- **Token_Tracker**: The subsystem that monitors and enforces per-tenant monthly token consumption limits for AI API calls
- **Action_Trigger**: A configurable automation that the AI_Agent can invoke during conversation (e.g., send invoice, create appointment, create ticket)
- **Business_Rule**: A tenant-configurable constraint that the AI_Agent must follow (e.g., maximum discount percentage, restricted topics)
- **Guardrail_Engine**: The validation layer that checks AI_Agent responses against Business_Rules, anti-hallucination policies, and compliance requirements before sending
- **Appointment_Scheduler**: The module that manages tenant availability slots and books appointments for contacts
- **Support_Ticket**: A structured record representing a customer issue, with type, priority, status, and assignment
- **Conversation_Summary**: A condensed representation of a long conversation generated by the AI to reduce token usage while preserving essential context


## Requirements

### Requirement 1: AI Agent Configuration

**User Story:** As a tenant administrator, I want to configure my AI Sales Agent with custom AI provider settings, system prompts, and behavior parameters, so that the agent reflects my business identity and communication style.

#### Acceptance Criteria

1. THE AI_Agent configuration API SHALL store per-tenant settings including AI provider URL, model name, API key, system prompt, temperature, and maximum response tokens
2. WHEN a tenant creates or updates AI_Agent configuration, THE Configuration_Service SHALL validate that the AI provider URL is reachable and the API key is functional by sending a test request
3. WHEN AI_Agent configuration is missing for a tenant, THE AI_Agent SHALL not process incoming messages and SHALL return a configuration-required status
4. WHEN a tenant updates AI_Agent configuration, THE Configuration_Service SHALL invalidate cached configuration in Cloudflare KV within 5 seconds
5. THE AI_Agent configuration SHALL support specifying the primary language (default: Bahasa Indonesia) and conversation tone parameters


### Requirement 2: Knowledge Base Management

**User Story:** As a tenant administrator, I want to manage a knowledge base of FAQs, product information, and business policies, so that my AI agent provides accurate and consistent answers.

#### Acceptance Criteria

1. THE Knowledge_Base API SHALL support CRUD operations for entries containing title, content (markdown), category, tags, and optional file attachments stored in R2
2. WHEN a knowledge base entry is created or updated, THE Knowledge_Base service SHALL generate and store a text embedding vector for semantic search retrieval
3. THE Product_Catalog SHALL support structured entries with name, description, price, currency, availability status, image URLs (R2), and custom attributes as JSON
4. WHEN the AI_Agent needs to answer a question, THE Knowledge_Base service SHALL return the top-K most relevant entries using semantic similarity search
5. THE Knowledge_Base API SHALL support bulk import of entries via JSON format with validation of required fields
6. IF a knowledge base entry references a file attachment, THEN THE Knowledge_Base service SHALL store the file in R2 under the tenant-scoped prefix and record the R2 key


### Requirement 3: AI Conversation Processing

**User Story:** As a customer, I want to have natural conversations with the AI agent via WhatsApp, so that I can get product information, resolve issues, and make purchases without waiting for a human.

#### Acceptance Criteria

1. WHEN an incoming WhatsApp message is received via Go-Wa webhook, THE AI_Agent SHALL retrieve the conversation context, query the Knowledge_Base, construct a prompt, and generate a response within 15 seconds
2. THE AI_Agent SHALL maintain conversation context by loading the most recent N messages (configurable per tenant, default 20) from the messages table for the contact
3. WHEN a conversation exceeds the configured context window, THE AI_Agent SHALL generate a Conversation_Summary to compress earlier messages while preserving key facts
4. THE AI_Agent SHALL format responses in natural Bahasa Indonesia (or the configured language) with appropriate tone matching the tenant system prompt
5. WHEN the AI_Agent generates a response, THE Guardrail_Engine SHALL validate the response against Business_Rules and anti-hallucination checks before sending via Go-Wa
6. IF the Guardrail_Engine rejects a response, THEN THE AI_Agent SHALL regenerate with additional constraints or escalate to a human agent


### Requirement 4: Sales Automation and Pipeline

**User Story:** As a business owner, I want the AI agent to guide customers through the full sales flow from inquiry to invoice, so that sales can be closed automatically without human intervention.

#### Acceptance Criteria

1. WHEN a customer expresses purchase intent, THE AI_Agent SHALL guide the conversation through product explanation, negotiation, and confirmation stages
2. WHEN a sale is confirmed by the customer, THE AI_Agent SHALL trigger the Action_Trigger to generate an invoice via the existing iPaymu billing service and send the payment link via WhatsApp
3. THE AI_Agent SHALL track each contact's position in the sales pipeline (inquiry, explanation, negotiation, closing, invoiced, paid) and update the pipeline stage in D1
4. WHEN negotiating price, THE AI_Agent SHALL respect Business_Rules for maximum discount percentage and minimum acceptable price per product
5. WHEN the AI_Agent sends an invoice, THE system SHALL record the transaction linking contact_id, product details, amount, and payment status
6. IF a payment link expires without payment, THEN THE AI_Agent SHALL send a follow-up reminder message to the customer via WhatsApp


### Requirement 5: Appointment Scheduling

**User Story:** As a customer, I want the AI agent to schedule appointments for me without back-and-forth, so that I can book a time slot in a single conversation.

#### Acceptance Criteria

1. THE Appointment_Scheduler SHALL maintain configurable availability slots per tenant including days of week, time ranges, slot duration, and buffer time between appointments
2. WHEN a customer requests an appointment, THE AI_Agent SHALL query the Appointment_Scheduler for available slots and present options to the customer
3. WHEN a customer confirms a time slot, THE Appointment_Scheduler SHALL create a booking record in D1 with contact_id, tenant_id, date, time, duration, and status
4. WHEN an appointment is booked, THE AI_Agent SHALL send a confirmation message to the customer via WhatsApp including date, time, and any preparation instructions
5. THE Appointment_Scheduler SHALL send reminder messages via WhatsApp 24 hours and 1 hour before the appointment using Cloudflare Queues for delayed delivery
6. IF a requested time slot is already booked, THEN THE AI_Agent SHALL suggest the nearest available alternatives


### Requirement 6: Customer Support Tickets

**User Story:** As a customer, I want my issues to be tracked and resolved through the AI agent, so that I get consistent follow-up and resolution without repeating my problem.

#### Acceptance Criteria

1. WHEN the AI_Agent identifies a customer issue from conversation, THE AI_Agent SHALL create a Support_Ticket in D1 with type, description, priority (low, medium, high, critical), and status (open)
2. THE AI_Agent SHALL categorize Support_Tickets by type (billing, technical, product, general) using conversation analysis
3. WHEN a Support_Ticket status changes, THE AI_Agent SHALL notify the customer via WhatsApp with the updated status and any resolution details
4. IF the AI_Agent cannot resolve an issue within 2 conversation turns, THEN THE AI_Agent SHALL escalate the ticket to a human agent and update ticket status to escalated
5. THE Support_Ticket API SHALL support listing, filtering by status and priority, and manual status updates by tenant staff
6. WHEN a ticket is resolved, THE AI_Agent SHALL send a resolution summary to the customer and ask for confirmation of satisfaction


### Requirement 7: Lead Qualification and Scoring

**User Story:** As a sales manager, I want the AI agent to automatically qualify and score leads based on conversation signals, so that my team can prioritize high-intent prospects.

#### Acceptance Criteria

1. WHEN a conversation occurs, THE Lead_Scorer SHALL analyze message content for purchase intent signals and assign a qualification score (hot, warm, cold) to the contact
2. THE Lead_Scorer SHALL use configurable scoring criteria per tenant including keywords, question patterns, response timing, and engagement level
3. WHEN a lead score changes, THE Lead_Scorer SHALL update the contact record in D1 with the new score and timestamp
4. THE Lead_Scorer SHALL tag contacts with qualification metadata accessible via the existing contacts API
5. WHEN a contact is scored as hot, THE AI_Agent SHALL notify designated staff via WhatsApp with the contact details and conversation summary


### Requirement 8: Guardrails and Compliance

**User Story:** As a tenant administrator, I want to configure business rules and compliance guardrails for the AI agent, so that it never shares sensitive information, offers unauthorized discounts, or hallucinates information.

#### Acceptance Criteria

1. THE Guardrail_Engine SHALL validate every AI_Agent response against the tenant's configured Business_Rules before sending to the customer
2. THE Guardrail_Engine SHALL detect hallucination by verifying that factual claims in the response can be traced to Knowledge_Base entries or the current conversation context
3. WHEN the Guardrail_Engine detects a rule violation, THE AI_Agent SHALL regenerate the response with the violated rule explicitly injected into the prompt
4. THE Business_Rule configuration SHALL support rule types including: maximum discount percentage, restricted topics, required disclaimers, and prohibited phrases
5. THE Guardrail_Engine SHALL maintain an audit log of all rule violations with the original response, the violated rule, and the corrected response
6. IF the AI_Agent is uncertain about an answer (confidence below configurable threshold), THEN THE AI_Agent SHALL respond with an admission of uncertainty and offer to escalate to a human


### Requirement 9: Human Escalation and Dynamic Knowledge

**User Story:** As a business owner, I want my AI agent to ask my staff for help when it encounters unfamiliar situations, and learn from their responses for future interactions, so that the AI continuously improves without manual training.

#### Acceptance Criteria

1. WHEN the AI_Agent encounters a question it cannot answer from the Knowledge_Base or conversation context, THE Escalation_Service SHALL send a natural-language inquiry to designated Staff_Contacts via WhatsApp
2. THE escalation message SHALL be phrased naturally (like a colleague asking for help) and include the customer question, relevant context, and the specific information needed
3. WHILE waiting for a staff response, THE AI_Agent SHALL inform the customer that it is checking with the team and provide an estimated wait time
4. WHEN a Staff_Contact replies to an escalation message, THE Escalation_Service SHALL route the response back to the AI_Agent and the AI_Agent SHALL use it to compose a reply to the customer
5. WHEN a staff response is received, THE Escalation_Service SHALL create a new Knowledge_Base entry from the staff's answer for future reference, tagged with the question context
6. THE Escalation_Service SHALL support configuring multiple Staff_Contacts per tenant with escalation priority order
7. IF no staff responds within a configurable timeout (default 30 minutes), THEN THE AI_Agent SHALL inform the customer that a human will follow up and create a Support_Ticket
8. THE Escalation_Service SHALL allow staff to proactively send information to the Knowledge_Base by messaging a designated command format


### Requirement 10: Conversation Context and Memory

**User Story:** As a customer, I want the AI agent to remember my previous interactions and preferences, so that I do not need to repeat information across sessions.

#### Acceptance Criteria

1. THE AI_Agent SHALL load the full conversation history for a contact from the messages table, limited to the configured context window (default 20 messages)
2. WHEN a conversation exceeds the context window, THE AI_Agent SHALL generate a Conversation_Summary that captures key facts, preferences, and unresolved items from earlier messages
3. THE Conversation_Summary SHALL be stored in D1 per contact and appended to the AI prompt as persistent memory across sessions
4. THE AI_Agent SHALL reference previous purchase history, appointment history, and ticket history when generating responses for returning customers
5. WHEN a new session starts with a returning contact, THE AI_Agent SHALL greet the contact with awareness of their last interaction topic and any pending items


### Requirement 11: Token Usage Tracking and Billing

**User Story:** As a platform operator, I want to track and enforce AI token consumption per tenant, so that I can bill accurately and prevent overuse.

#### Acceptance Criteria

1. THE Token_Tracker SHALL record prompt tokens and completion tokens for every AI API call, storing tenant_id, model, token counts, and timestamp in D1
2. THE Token_Tracker SHALL maintain a running monthly total per tenant cached in Cloudflare KV for fast quota checking
3. WHEN a tenant's monthly token usage reaches the configured limit, THE AI_Agent SHALL stop processing new messages and inform customers that the service is temporarily unavailable
4. THE Token_Tracker SHALL expose an API endpoint returning current usage, remaining quota, and usage history per tenant
5. WHEN a tenant reaches 80% of their monthly quota, THE Token_Tracker SHALL send a warning notification to the tenant administrator via WhatsApp
6. THE Token_Tracker SHALL reset monthly counters on the first day of each month using a scheduled Cloudflare Worker (cron trigger)


### Requirement 12: Action Triggers and Integrations

**User Story:** As a tenant administrator, I want to configure actions that the AI agent can trigger during conversations, so that it can perform real tasks like sending invoices, booking appointments, and creating tickets autonomously.

#### Acceptance Criteria

1. THE Action_Trigger system SHALL support a registry of configurable actions per tenant including: send_invoice, create_appointment, create_ticket, update_pipeline, notify_staff, and custom webhook
2. WHEN the AI_Agent determines an action should be triggered (based on conversation intent), THE AI_Agent SHALL invoke the corresponding Action_Trigger with structured parameters extracted from the conversation
3. THE Action_Trigger SHALL validate parameters against a schema before execution and reject invalid invocations with a descriptive error
4. WHEN an action completes successfully, THE Action_Trigger SHALL return a result that the AI_Agent incorporates into its next response to the customer
5. THE Action_Trigger SHALL emit webhook notifications to tenant-configured URLs for every completed action with action type, parameters, result, and timestamp
6. IF an Action_Trigger execution fails, THEN THE AI_Agent SHALL inform the customer of the issue and offer alternatives or escalation


### Requirement 13: Unified Conversation Inbox

**User Story:** As a tenant staff member, I want to view all AI and human conversations in a unified inbox, so that I can monitor AI interactions, take over conversations, and add notes.

#### Acceptance Criteria

1. THE Conversation API SHALL return paginated conversation threads grouped by contact, including message history, channel indicator, AI/human sender flag, and timestamps
2. WHEN a staff member assigns themselves to a conversation, THE AI_Agent SHALL pause automatic responses for that contact and route messages to the assigned staff
3. WHEN a staff member releases a conversation, THE AI_Agent SHALL resume automatic response processing for that contact
4. THE Conversation API SHALL support adding internal notes and tags to conversations that are visible only to tenant staff
5. THE Conversation API SHALL indicate the current pipeline stage, lead score, and active tickets for each conversation thread


### Requirement 14: Conversation Audit and Analytics

**User Story:** As a tenant administrator, I want to review AI conversation quality and audit guardrail interventions, so that I can improve my AI configuration and ensure compliance.

#### Acceptance Criteria

1. THE Audit_Service SHALL log every AI_Agent interaction including: input message, retrieved knowledge base entries, generated prompt, raw AI response, guardrail result, final sent message, and token usage
2. THE Audit_Service SHALL store audit logs in D1 with tenant_id scoping and support pagination and date-range filtering
3. WHEN a guardrail violation occurs, THE Audit_Service SHALL flag the interaction with violation type, the Business_Rule violated, and the corrected response
4. THE Analytics API SHALL provide aggregated metrics per tenant including: total conversations, messages processed, actions triggered, escalations, average response time, and lead conversion rate
5. THE Audit_Service SHALL retain audit logs for a configurable period (default 90 days) and purge expired records via scheduled Cloudflare Worker
